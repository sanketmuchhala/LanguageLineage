JAX

J

JAX is a Python library for numerical arrays and composable program transformations. It can differentiate a function, vectorize it across an array axis and compile it with XLA. That combination makes its implementation interesting: Python expresses the calculation, transformations change that calculation, and a compiler produces an executable for the selected backend. [JAX transformations]

What is JAX written in?

JAX compiler is built on XLA (well-documented). Its runtime is implemented in Python and C++ (documented).

What grad, vmap and jit each contribute

jax.grad creates a function computing derivatives. jax.vmap maps a function over array axes by transforming its primitive operations, rather than simply writing a Python loop around repeated calls. jax.jit compiles a function. These transformations can be composed: for example, a batched gradient calculation can itself be compiled. The order and meaning of those transformations are part of the program, not merely installation settings. [JAX transformations]

JAX offers a NumPy-like interface, but its central idea extends beyond an array library. Transformations operate on numerical functions and can be combined with device placement and distributed array facilities. This separates the language used to express the computation from the mechanism that executes it. The graph’s XLA connection records a compiler relationship, not a programming language in which every part of JAX was authored. [JAX transformations]

What happens the first time a compiled function runs

During tracing, JAX wraps arguments in tracer objects and records the operations performed on them. The resulting jaxpr represents the numerical computation. XLA compiles the traced computation, and later compatible calls reuse compiled code. The first invocation therefore includes work that steady-state calls may avoid. A cold-call measurement and a reused-executable measurement answer different performance questions. [JAX tracing and JIT compilation]

Why ordinary Python side effects can be surprising

A Python print or mutation can happen while JAX traces the function without becoming an operation in the compiled computation. JAX transformations are designed around pure functions, so modifying global state is not a reliable way to express repeated device-side behavior. The documentation provides dedicated debugging and callback facilities. A function being valid Python is therefore insufficient to establish that its behavior survives transformation as intended. [JAX tracing and JIT compilation]

Dispatch is different from completion

JAX can return an array representing a result that the accelerator has not finished computing. The host may inspect shape and type or enqueue dependent operations without waiting for the actual values. Reading a value on the host forces the relevant computation to complete. This lets Python submit work ahead of the device, reducing avoidable gaps between operations. [JAX asynchronous dispatch]

A benchmark that stops when the Python call returns can therefore measure dispatch rather than execution. The documented block_until_ready method waits for the result without requiring a host-side NumPy conversion. Distinguish compilation time, submission time, execution time and data-transfer time when comparing results. Otherwise a seemingly fast calculation may simply be unfinished when the stopwatch stops. [JAX asynchronous dispatch]
