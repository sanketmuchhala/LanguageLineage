How Does llama.cpp Run a Model on Your Hardware?

llama.cpp is plain C/C++: your program calls the llama.cpp library, which loads a GGUF model file and builds a ggml compute graph for each step of inference. ggml then runs that graph on a backend. On the CPU it uses SIMD kernels written in C/C++; on an NVIDIA GPU it runs CUDA kernels that nvcc compiled when llama.cpp was built; on Apple silicon it runs kernels written in Metal Shading Language. With a GPU backend, layers that are not offloaded to the GPU still run on the CPU.

The selected path, step by step

  1. Your program calls llama.cpp library: The program calls the llama.cpp library, which is plain C/C++ with no other dependencies.
  2. llama.cpp library loads GGUF model file: The library reads the model's weights and metadata from a GGUF file.
  3. llama.cpp library builds ggml compute graph: For each step of generation, llama.cpp describes the computation as a ggml graph.
  4. ggml compute graph runs layers on ggml CPU backend: With the CPU backend the whole graph runs here. With a GPU backend, the layers not offloaded to the GPU still run here; --n-gpu-layers controls the split.
  5. ggml compute graph offloads layers to ggml Metal backend: On macOS builds Metal is on by default, and the offloaded layers are computed by the Metal backend. --n-gpu-layers 0 turns GPU inference off.
  6. ggml CPU backend runs on CPU: The C/C++ kernels run on the CPU's cores using its SIMD instructions.
  7. ggml Metal backend kernels written in Metal kernels (MSL): The Metal backend's operations are llama.cpp's own kernels in Metal Shading Language.
  8. Metal kernels (MSL) run on Apple silicon GPU: Through Apple's Metal framework the kernels run on the Apple silicon GPU.

Which language does the work

There is no Python on this path. The library, the model loader and ggml are C and C++, and the language of the innermost loops depends on the backend: C/C++ with SIMD instructions on the CPU, CUDA C++ on NVIDIA GPUs, and Metal Shading Language on Apple GPUs.

The GPU kernels are written for each backend and kept in the llama.cpp repository. CUDA kernels are compiled by NVIDIA's nvcc when llama.cpp itself is built, by default for the GPU in the build machine. That is a different arrangement from torch.compile, where TorchInductor generates new kernels while your program runs.

CPU and GPU together

With the CUDA or Metal backend, the GPU only runs the layers offloaded to it, which the --n-gpu-layers (-ngl) option controls. The rest of the model runs on the CPU backend, which is how llama.cpp runs models larger than the GPU's memory.

GGUF model file

model format

The model's weights and metadata in one binary file. GGUF is a file format, not a programming language.

  • GGUF is a file format for storing models for inference with GGML and executors based on GGML.
    GGUF specification (ggml) Source repository

ggml compute graph

framework component

ggml, the C/C++ tensor library under llama.cpp, records the operations of each step as a graph, then hands it to a backend to compute.

In the atlas: ggml

  • ggml is a machine learning (ML) library written in C and C++ with a focus on Transformer inference.
    Introduction to ggml (Hugging Face blog, by ggml maintainers) Project docs
  • ggml_cgraph : Represents a computational graph. Think of it as the "order of computation" that will be transferred to the backend.
    Introduction to ggml (Hugging Face blog, by ggml maintainers) Project docs

ggml CPU backend

kernel

C/C++ kernels using the CPU's SIMD instructions: AVX on x86, NEON on ARM, including Apple silicon.

In the atlas: ggml

  • AVX, AVX2, AVX512 and AMX support for x86 architectures
    llama.cpp README Source repository
  • Apple silicon is a first-class citizen - optimized via ARM NEON, Accelerate and Metal frameworks
    llama.cpp README Source repository

ggml CUDA backend

framework component

The backend for NVIDIA GPUs, enabled at build time with -DGGML_CUDA=ON. It runs llama.cpp's own CUDA kernels.

In the atlas: ggml

  • Custom CUDA kernels for running LLMs on NVIDIA GPUs
    llama.cpp README Source repository
  • This provides GPU acceleration using an NVIDIA GPU.
    llama.cpp build guide Source repository
  • cmake -B build -DGGML_CUDA=ON
    llama.cpp build guide Source repository

ggml Metal backend

framework component

The backend for Apple GPUs, enabled by default on macOS. It runs llama.cpp's own Metal kernels through Apple's Metal framework.

  • On MacOS, Metal is enabled by default. Using Metal makes the computation run on the GPU.
    llama.cpp build guide Source repository
  • Apple silicon is a first-class citizen - optimized via ARM NEON, Accelerate and Metal frameworks
    llama.cpp README Source repository

NVIDIA's CUDA compiler. It compiles the CUDA kernels when llama.cpp is built, by default for the GPU in the build machine.

What this does not show

Documented paths for running a GGUF model with llama.cpp on three of its backends: the CPU, CUDA on an NVIDIA GPU, and Metal on Apple silicon. Other backends (Vulkan, HIP, SYCL, OpenCL and more), multi-GPU and RPC setups, and how a model is converted to GGUF are out of scope. The same ggml graph can run on any backend the build enables; this page shows three of them.
