How AI frameworks run your code

Each explainer below traces one AI framework from the line of code you write to the chip that runs it. Pick a mode and a device, and the diagram shows which stages your code passes through. Every stage and every arrow quotes the official documentation or source code that supports it.

Where every path converges

All 53 selectable paths across the 12 explainers, from the framework on the left, through the atlas tools that at least two explainers share, to the hardware they reach. Thicker lines carry more paths. PyTorch and CUDA sit on the most paths; NVIDIA GPU (23), AMD GPU (2), Apple silicon GPU (7), Google TPU (2), CPU (20), Configured GPU (3) are the targets. Select a framework, tool or chip to trace only its paths.

Where your code hands over

The default path of each explainer, one block per stage in execution order, coloured by the layer its data file assigns. The white bar marks where your own code ends and the framework takes over; outlined blocks after the chip are side stages (a cache, a detokenizer, post-processing) whose place along the line the sources do not fix. Keras and TensorFlow have the shortest default paths (5 stages) and vLLM the longest (14). More stages means more documented layers, not slower code. How these pages are built

Each explainer is one versioned JSON file (how-jax-runs.json, how-keras-runs.json, how-llama-cpp-runs.json, how-mlx-runs.json, how-ollama-runs.json, how-onnx-runtime-runs.json, how-pytorch-runs.json, how-sglang-runs.json, how-tensorflow-runs.json, how-tensorrt-llm-runs.json, how-transformers-runs.json, how-vllm-runs.json) under the same CC BY 4.0 license as the dataset. They are kept apart from the language lineage graph on purpose: "lowers to" and "dispatches to" describe how code executes, not what a tool is written in. Closed systems are not guessed at; where the public documentation stops, the diagram stops too. Found a mistake? Open an issue with the better source.
