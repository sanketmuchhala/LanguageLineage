What Actually Happens When You Run a Hugging Face Pipeline?

A pipeline() call runs four documented stages: tokenization, model inference, post-processing and output. The tokenizer turns text into token ids with Hugging Face's Rust tokenizers library. The model is a PyTorch module whose weights from_pretrained() loads from safetensors files when they exist. generate() then calls the model one step at a time, by default greedily keeping the most likely next token, up to 20 new tokens unless the model's config says otherwise. Attention runs through PyTorch's SDPA, which picks the fastest kernel on a CUDA GPU and the C++ implementation on the CPU; on Apple silicon the operations run as MPS kernels. The output ids are decoded back into text.

The selected path, step by step

  1. Your pipeline() call creates and calls Pipeline: Your code builds a pipeline for a task and calls it with text.
  2. Pipeline loads safetensors weights: The model's weights are loaded with from_pretrained(), from safetensors files when available.
  3. safetensors weights fill PyTorch model: The weights are loaded into the model class on the chosen device.
  4. Pipeline tokenizes with Tokenizer (Rust core): Input text is tokenized first.
  5. Tokenizer (Rust core) token ids go to generate() loop: The token ids start the generation loop.
  6. generate() loop calls forward, one token at a time PyTorch model: Each step runs the model and, with greedy search, keeps the most likely next token.
  7. PyTorch model computes attention with PyTorch SDPA: Unless another attention implementation is set, attention layers use PyTorch's SDPA.
  8. PyTorch SDPA picks Fastest CUDA kernel: On a CUDA GPU, SDPA selects the fastest available attention kernel.
  9. Fastest CUDA kernel runs on NVIDIA GPU: The kernels run on the NVIDIA GPU.
  10. generate() loop hands output ids to Post-processing: The finished token ids go to post-processing.

Which device it picks

If you do not pass a device, the pipeline places the model on the first accelerator it finds (a CUDA GPU, Apple silicon's MPS, or others) and uses the CPU only when there is none. Passing device="cpu" or device="mps" forces a choice.

Where Python hands off

Most of the work in this path is not Python: tokenization runs in Rust, and the model's layers run as PyTorch kernels. For what PyTorch does with those operations on each device, see what happens when you run a PyTorch model. For serving many requests at once, engines such as vLLM and SGLang add batching schedulers and KV-cache management on top of the same kind of model.

Every stage

Your pipeline() call

programming language

Python code such as pipeline(task="text-generation", model=...), which picks a default model and preprocessor for the task unless you name one.

In the atlas: Python

  • Each task is configured to use a default pretrained model and preprocessor, but this can be overridden with the model parameter if you want to use a different model.
    Pipeline (Transformers documentation) Project docs

Pipeline

framework component

Transformers' Pipeline class: tokenization, model inference and post-processing in one call, on the device it chooses or you set.

In the atlas: Transformers

  • Pipeline workflow is defined as a sequence of the following operations: Input -> Tokenization -> Model Inference -> Post-Processing (task dependent) -> Output
    Pipelines API reference (Transformers documentation) Project docs

safetensors weights

model format

The model's configuration and weights from the Hugging Face Hub or a local folder, read from safetensors files when they exist.

In the atlas: Safetensors

  • The from_pretrained() method loads weights stored in the safetensors file format if they’re available.
    Loading models (Transformers documentation) Project docs

Tokenizer (Rust core)

framework component

Turns text into token ids. Fast tokenizers run on the Rust tokenizers library, which parallelizes batches across threads.

In the atlas: HF Tokenizers

  • TokenizersBackend handles large batches faster because its Rust-based backend parallelizes work across threads.
    Tokenizers (Transformers documentation) Project docs

PyTorch model

framework component

The model class (for text generation, a causal language model) holding the loaded weights on the chosen device.

In the atlas: PyTorch

  • It requires a model class and the from_pretrained() method.
    Loading models (Transformers documentation) Project docs

generate() loop

runtime

Produces new tokens one step at a time by calling the model; by default it is greedy search, up to 20 new tokens unless the model's generation config says otherwise.

  • Greedy search is the default decoding strategy. It selects the next most likely token at each step.
    Generation strategies (Transformers documentation) Project docs
  • Unless specified in GenerationConfig , this strategy generates a maximum of 20 new tokens.
    Generation strategies (Transformers documentation) Project docs

Post-processing

framework component

Turns the output token ids back into text for the result.

  • Postprocess will receive the raw outputs of the _forward method, generally tensors, and reformat them into something more friendly.
    Pipelines API reference (Transformers documentation) Project docs

PyTorch SDPA

kernel

Transformers' default attention function: PyTorch's scaled dot product attention.

In the atlas: PyTorch

  • Omit certain backbones from the dict to use the default attention function (SDPA).
    Attention backends (Transformers documentation) Project docs

C++ attention

kernel

On backends other than CUDA, SDPA uses PyTorch's C++ implementation.

In the atlas: C++

  • It defaults to the PyTorch C++ implementation for other backends.
    Attention backends (Transformers documentation) Project docs

MPS kernels

kernel

On the mps device, PyTorch runs operations as Metal Performance Shaders graphs and kernels.

  • It introduces a new device to map Machine Learning computational graphs and primitives on highly efficient Metal Performance Shaders Graph framework and tuned kernels provided by Metal Performance Shaders framework respectively.
    MPS backend (PyTorch 2.15 documentation) Project docs

Fastest CUDA kernel

kernel

On CUDA, SDPA automatically picks the fastest available attention kernel.

In the atlas: CUDA

  • PyTorch’s scaled dot product attention (SDPA) selects the fastest attention function for CUDA backends automatically.
    Attention backends (Transformers documentation) Project docs

CPU

hardware

Used only when no accelerator is available, or when you pass device="cpu".

  • By default, when device is left unset, Pipeline automatically places the model on the first available accelerator (CUDA GPU, Apple Silicon MPS, XPU, …) and only falls back to a CPU when none is available.
    Pipeline (Transformers documentation) Project docs

Apple silicon GPU

hardware

The GPU of an Apple silicon Mac, through PyTorch's mps device.

  • To run Pipeline on Apple silicon, set device="mps".
    Pipeline (Transformers documentation) Project docs

NVIDIA GPU

hardware

The first choice when device is left unset and a CUDA GPU is present.

  • By default, when device is left unset, Pipeline automatically places the model on the first available accelerator (CUDA GPU, Apple Silicon MPS, XPU, …) and only falls back to a CPU when none is available.
    Pipeline (Transformers documentation) Project docs

What this does not show

Documented path for one text-generation pipeline() call with the PyTorch backend, default greedy decoding and the default SDPA attention, on a CPU, an NVIDIA GPU or an Apple silicon GPU. Other tasks, other attention implementations (FlashAttention, paged attention), quantization, multi-GPU placement with device_map, Accelerate and other frameworks are out of scope. What happens inside PyTorch on each device is on the PyTorch page.
